# 实验五 利用鲲鹏处理器的流水线来优化汇编代码性能

## 1. 实验介绍
### 1.1 关于本实验
实现 GNU ARM 汇编中如何利用 AArch64 架构“其访存单元支持每拍 2 条读或写访存指令”的特性，提升代码执行效率。

### 1.2 教学目标
掌握在 AArch64 架构下提高汇编代码执行效率的方式。

### 1.3 实验内容介绍
关于在 C 代码和汇编代码之间进行参数传递，根据 Arm 公司的 AAPCS64（AArch64 程序调用标准）：
AArch64 标准提供了 8 个通用寄存器（x0-x7）用于传递函数参数，依次对应参数 0、参数 1、参数 2……参数 7。
第 8 个参数可通过 sp 访问，第 9 个参数可通过 sp + 8 访问，第 n 个参数可通过 sp + 8*(n-8) 访问。
一般来说，只带少量参数的函数仅使用寄存器即可；超过 8 个参数时，额外参数存放在栈中传递给子程序。
本例中需要传递 3 个参数：
- 第 1 个参数：目标字符串首地址，用寄存器 X0 传递。
- 第 2 个参数：源字符串首地址，用寄存器 X1 传递。
- 第 3 个参数：传输字节数，用寄存器 X2 传递。

在使用 ldrb/ldp 和 str/strb/stp 等访存指令时，要注意区分三种地址形式：
- 前索引方式，形如：ldrb w2, [x1, #1]
  - 将 x1+1 指向地址处的一个字节放入 w2；x1 的值保持不变。
- 前索引写回（自动索引）方式，形如：ldrb w2, [x1, #1]!
  - 将 x1+1 指向地址处的一个字节放入 w2；然后 x1+1 -> x1。
- 后索引方式，形如：ldrb w2, [x1], #1
  - 将 x1 指向地址处的一个字节放入 w2；然后 x1+1 -> x1。

该程序由两部分组成：
- 第一部分是主函数（Linux C 语言），用于测试 memorycopy 函数的执行时间。
- 第二部分是内存拷贝函数（GNU Arm64 汇编）。

为了较准确测量 memorycopy() 执行时间，调用 clock_gettime() 分别记录执行前后时间，以纳秒计时。
虽然运行平台是 NVIDIA Jetson Orin Nano，但同属 ARMv8，可验证指令集行为。

## 2. 实验任务操作指导
### 2.1 创建原始示例程序源码
以下步骤以在华为鲲鹏云服务器上执行为例。

步骤 1：执行以下命令，创建 memorycopy 目录存放该程序的所有文件，并进入该目录。

```bash
cd
mkdir memorycopy
cd memorycopy
```

步骤 2：执行以下命令，创建主函数 Linux C 代码 memorycopy.c。

```bash
vim memorycopy.c
```

代码内容如下：

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#define len 60000000
char src[len], dst[len];
long int len1 = len;
extern void memorycopy(char *dst, char *src, long int len1);
int main()
{
    struct timespec t1, t2;
    int i, j;
    for (i = 0; i < len - 1; i++)
    {
        src[i] = 'a';
    }
    src[i] = 0;
    clock_gettime(CLOCK_MONOTONIC, &t1);
    memorycopy(dst, src, len1);
    clock_gettime(CLOCK_MONOTONIC, &t2);
    printf("memorycopy time is %11u ns\n", t2.tv_nsec - t1.tv_nsec);
    return 0;
}
```

步骤 3：执行以下命令，创建内存拷贝函数 GNU Arm64 汇编代码 copyfunc.s。

```bash
vim copyfunc.s
```

代码内容如下：

```asm
.global memorycopy
memorycopy:
ldrb w3, [x1], #1
strb w3, [x0], #1
sub x2, x2, #1
cmp x2, #0
bne memorycopy
ret
```

说明：内存拷贝函数 memorycopy() 的功能是将尺寸为 len（这里设为 60000000）的 src 字符数组内容拷贝到同样尺寸的 dst 字符数组中。
memorycopy() 用 Arm64/AArch64 汇编实现。根据访存指令和循环展开粒度不同，可有多种实现。以上汇编代码是最原始方式：不循环展开，每次循环只使用 1 个 ldrb 和 1 个 strb。

### 2.2 进行原始程序的编译运行
保存示例源码文件，退出 vim 编辑器。在当前目录中依次执行以下命令进行编译运行。

```bash
gcc copyfunc.s memorycopy.c -o m1
./m1
```

通过运行可见，原始方法编写的 memorycopy 示例程序可成功编译与运行，并输出执行时间（示例：46620054 纳秒）。

### 2.3 代码的第一阶段改进
采用循环展开方法，充分利用流水线多发射机制，对 memorycopy() 原始汇编主体做两种改进。

方法 1：循环展开宽度为 2。命名为 copyfunc_v2_1.s，汇编代码如下：

```asm
.global memorycopy
memorycopy:
sub x1, x1, #1
sub x0, x0, #1
lp:
ldrb w3, [x1, #1]
ldrb w4, [x1, #2]!
strb w3, [x0, #1]
strb w4, [x0, #2]!
sub x2, x2, #2
cmp x2, #0
bne lp
ret
```

方法 2：循环展开宽度为 4。命名为 copyfunc_v2_2.s，汇编代码如下：

```asm
.global memorycopy
memorycopy:
sub x1, x1, #1
sub x0, x0, #1
lp:
ldrb w3, [x1, #1]
ldrb w4, [x1, #2]
ldrb w5, [x1, #3]
ldrb w6, [x1, #4]!
strb w3, [x0, #1]
strb w4, [x0, #2]
strb w5, [x0, #3]
strb w6, [x0, #4]!
sub x2, x2, #4
cmp x2, #0
bne lp
ret
```

### 2.4 代码第一阶段改进版的编译运行
分别保存两段新的汇编源码，并退出 vim。在当前目录中依次执行以下命令：

```bash
gcc copyfunc_v2_1.s memorycopy.c -o m21
./m21
gcc copyfunc_v2_2.s memorycopy.c -o m22
./m22
```

从测试结果可见，两种改进代码性能都优于原始代码，两者之间性能差距不大。

原因分析：鲲鹏 920 有两条 load/store 流水线，其访存单元支持每拍 2 条读或写访存操作。
原始代码中源和目标地址的一读一写交替，访存连续性差、cache 命中率较低；且循环分支指令较多，会频繁刷新流水线，降低访存指令发射队列填充速度。
改进代码有效缓解这些问题，从而降低访存延时。

### 2.5 代码的第二阶段改进
第一次改进中每次读/写内存仍以 1 字节为单位，访存效率较低。
可采用一次读/写 16 字节的方法，利用内存突发传输优势（连续读/写多个数据优于非连续方式），对上一节代码再次改进。
Arm64/AArch64 提供 ldp 和 stp 指令，可一次访问 16 字节数据，读/写连续性高，可有效降低访存延时。
使用 ldp/stp 的三种典型改进方式如下：

方法 1：不循环展开。命名为 copyfunc_v3_1.s，代码如下：

```asm
.global memorycopy
memorycopy:
ldp x3, x4, [x1], #16
stp x3, x4, [x0], #16
sub x2, x2, #16
cmp x2, #0
bne memorycopy
ret
```

方法 2：循环展开宽度为 2。命名为 copyfunc_v3_2.s，代码如下：

```asm
.global memorycopy
memorycopy:
sub x1, x1, #16
sub x0, x0, #16
lp:
ldp x3, x4, [x1, #16]
ldp x5, x6, [x1, #32]!
stp x3, x4, [x0, #16]
stp x5, x6, [x0, #32]!
sub x2, x2, #32
cmp x2, #0
bne lp
ret
```

方法 3：循环展开宽度为 4。命名为 copyfunc_v3_3.s，代码如下：

```asm
.global memorycopy
memorycopy:
sub x1, x1, #16
sub x0, x0, #16
lp:
ldp x3, x4, [x1, #16]
ldp x5, x6, [x1, #32]
ldp x7, x8, [x1, #48]
ldp x9, x10, [x1, #64]!
stp x3, x4, [x0, #16]
stp x5, x6, [x0, #32]
stp x7, x8, [x0, #48]
stp x9, x10, [x0, #64]!
sub x2, x2, #64
cmp x2, #0
bne lp
ret
```

### 2.6 代码第二阶段改进版的编译运行
分别保存三段新的汇编源码，并退出 vim。在当前目录中依次执行以下命令：

```bash
gcc copyfunc_v3_1.s memorycopy.c -o m31
./m31
gcc copyfunc_v3_2.s memorycopy.c -o m32
./m32
gcc copyfunc_v3_3.s memorycopy.c -o m33
./m33
```

经测试，上述三种改进代码性能明显高于第一阶段改进代码。

在上述改进代码中，同类型访存指令之间（如各 ldrb 之间、各 stp 之间）没有依赖关系（既无寄存器资源依赖，也无数据依赖）。
因此循环展开后可充分利用两条 load/store 流水线并行执行这些访存指令，从而提升访存性能。
如果改进代码中访存指令存在依赖关系，例如：

```asm
ldrb w3, [x1], #1
ldrb w4, [x1], #1
```

后一条 ldrb 的 x1 取值依赖前一条 ldrb 更新后的 x1，这种情况下改进效果会差很多。
可自行编写有依赖关系版本，与无依赖关系版本进行性能对比。

### 2.7 使用 nvcc 进行 GPU 内存拷贝测速（扩展）
为了进一步验证在 Jetson Orin 平台上利用 GPU 进行高吞吐拷贝，可使用 nvcc 版本程序进行对比测试。

示例命令：

```bash
nvcc -O3 -lineinfo -o exp5_cuda_memcpy_bench memorycopy_cuda_bench.cu
./exp5_cuda_memcpy_bench
```

该测试程序同时测量：
- Device-to-Device 的 cudaMemcpyAsync 拷贝性能。
- 向量化 CUDA kernel 拷贝性能。

并输出总耗时、等效带宽（GB/s）以及最佳路径（Best path）。
